#### Step 1: View all constrains across all tables
+ Open Neon's SQL editor and paste this query:
```sql
SELECT
    conrelid::regclass AS table_name,
    conname AS constraint_name,
    CASE contype
        WHEN 'c' THEN 'CHECK'
        WHEN 'f' THEN 'FOREIGN KEY'
        WHEN 'p' THEN 'PRIMARY KEY'
        WHEN 'u' THEN 'UNIQUE'
    END AS constraint_type,
    pg_get_constraintdef(oid) AS constraint_definition
FROM pg_constraint
WHERE connamespace = 'public'::regnamespace
ORDER BY table_name, constraint_type, constraint_name;
```
+ For convenience, the result is exported to `ANSER-v2-database\all_constrain.json`.

#### Step 6 (Additional fix): Preventing Read-Check-Write race condition
- A Read-Check-Write race condition happens when two or more concurrent API requests try to sell the same product at the exact same time.

- First, we look at where the Read-Check transaction happen:
```ts
const [product] = await tx.select().from(products).where(eq(products.id, productId)).limit(1);
    if (!product) {
        throw new ProductNotFoundError(...);
    }
    if (product.stock < quantity) {
        throw new InsufficientStockError(...);
    }
```
+ Standard PostgreSQL `SELECT` queries do not lock rows (default `READ COMMITTED` mode) = `tx.select()` reads `product.stock` into application memory without locking the row in database.

- Then we look at the Unconditional Write transaction:
```ts
await tx
    .update(products)
    .set({ stock: sql`${products.stock} + ${-item.quantity}`, updatedAt: new Date() })
    .where(eq(products.id, item.productId));
```
+ The `update()` only checks `WHERE id = productId` without checking if `stock >= quantity` at execution time.
+ E.g: Product A has `stock = 5`
    * User 1 requests 4 units. product.stock is 5 ($5 \ge 4$), check passes.
    * User 1's update runs: stock becomes $5 - 4 = 1$.
    * User 2 (simultaneously) requests 3 units. product.stock is still 5 ($5 \ge 3$), check passes.
    * User 2's update runs: stock becomes $1 - 3 = -2$

- To fix this, we simply lock the row until transaction finishes:
```ts
const [product] = await tx
    .select()
    .from(products)
    .where(eq(products.id, productId))
    .limit(1)
    .for("update"); // Lock the product row until transaction commits
```
